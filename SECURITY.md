# Security and publication

Report suspected vulnerabilities privately to markerickserrano1@gmail.com.
Do not include real student records, credentials, or other private information in public issues or pull requests.

## Repository access

Public access allows reading, cloning, and forking. It does not grant write access to this repository or its production deployment.
The production branch is `main`. Repository rules restrict updates to the owner and prohibit force pushes and deletion. Review these settings before inviting collaborators or granting an app write access.
Keep GitHub and Vercel accounts protected with two-factor authentication or passkeys. Review authorized apps, active sessions, tokens, deploy hooks, and account membership periodically.

## Local development

- Keep `.claude/`, `.kilo/`, `node_modules/`, environment files, and private backups out of Git.
- The static portfolio is in `public/`. Only that directory should be published.
- The optional map development project is in `map/web/`. Install its locked dependencies with `npm ci` and build with `npm run build`.
- Keep the Vite development server bound to `127.0.0.1`. Do not expose a development server as a production site.
- Review dependency security alerts and update the lockfile before publishing affected code.

## Browser security

Vercel and Apache header configuration is generated by `node tools/update-security-headers.mjs`.
Run it after changing inline scripts, then run `node tools/update-security-headers.mjs --check` and verify the site in a browser.
Keep external script and connection origins limited to the services the portfolio uses.
The Vercel configuration enables automatic Git deployments only for `main`; verify the production branch and fork protections in the Vercel project settings too.

## Images, records, and permissions

Public school-system screenshots must contain synthetic data or reviewed, flattened redactions. Do not publish original pupil records, learner IDs, grades, family details, staff photos, or account information without an appropriate basis for public disclosure.
The coordinate masks in `tools/redact-school-screenshots.py` apply only to the reviewed screenshot set. New or changed screenshots need a fresh privacy review; do not assume the same masks will cover them.
Keep untouched originals and any full Git backups outside this repository and outside the published directory, with access restricted to authorized people.

Replacing a public file does not erase previous Git commits, forks, cached files, or old hosting deployments. Handle any history cleanup separately, keep a private backup, and verify every public branch and tag afterward. Sensitive cached content may require help from GitHub Support or the hosting provider.

Confirm permission for client work, other people's artwork and photographs, logos, and project contributions before publication. Retain third-party license notices. This policy is a maintenance guide, not a legal certification or a guarantee about future content or laws.
